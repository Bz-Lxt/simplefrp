# SimpleFrp 需求文档

> 版本：v1.0（冻结） 日期：2026-08-20
> 来源：`docs/.meta/original_prompt.md`

## 1. 项目概述

使用 Go 语言实现简易版内网穿透工具（FRP/NPS 的核心子集），代号 **SimpleFrp**。
包含两个可执行程序：**Server 端**（部署在公网）与 **Client 端**（部署在内网）。
Client 主动与 Server 建立长连接形成 TCP 隧道，Server 将公网访客流量经隧道转发至内网服务。

## 2. 功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-1 | Server 控制监听 | Server 监听控制端口，接收 Client 注册（含 token 鉴权） |
| FR-2 | Server 访客监听 | Server 监听公网访客端口，接受外部 TCP 连接 |
| FR-3 | Client 长连接 | Client 启动后连接 Server 控制端口并保持长连接，断线自动重连 |
| FR-4 | 流量转发 | 访客连接 ↔ 隧道 ↔ Client ↔ 内网服务 的双向字节流转发 |
| FR-5 | 多路复用 | 单条 TCP 隧道上复用多条逻辑流（采用 yamux/smux 或等价自实现），流间互不阻塞 |
| FR-6 | 连接池管理 | Client 侧维护工作连接/会话池：按需创建、空闲复用、上限控制、空闲回收 |
| FR-7 | 配置化 | 监听地址、token、内网服务地址、池大小等通过配置文件 + 环境变量覆盖 |
| FR-8 | 可观测 | 统一结构化日志（level 可控），关键事件：注册、建流、转发、断连、重连 |

## 3. 非功能需求

- **Docker 交付（红线）**：`docker compose up` 一键启动 `server` + `client` + `demo`（模拟内网 Web 服务）三容器；镜像支持 ARM64/AMD64；容器时区 `TZ=Asia/Shanghai`。
- **localhost 可验证（红线适配）**：本项目为 CLI/网络工具，采用「容器化演示链路」策略满足交付标准——用户访问 `http://localhost:<访客端口>`，流量经 Server → 隧道 → Client → 内网 demo 服务，返回 HTTP 200 即证明全链路可用。
- **测试**：核心包单元测试（帧编解码、多路复用、连接池、转发）+ API/链路 smoke 测试（Mock 模式，成本 ¥0）。
- **无外部计费依赖**：纯 TCP 网络编程，无任何外部 API。

## 4. 验收基线（可测量）

| 指标 | 基线 |
|---|---|
| 隧道建立 | Client 启动后 ≤ 3s 完成注册，日志可见 |
| 转发正确性 | `curl http://localhost:<访客端口>/` 返回 200 且 body 与 demo 服务直连结果一致 |
| 多路复用 | 单条隧道承载 ≥ 32 并发逻辑流，无串流、无丢包 |
| 并发能力 | ≥ 100 并发访客连接全部成功 |
| 断线重连 | 杀掉 Server 并重启后，Client ≤ 10s 自动重连且转发恢复 |
| 连接池 | 池上限生效（超出排队/拒绝有日志），空闲连接按 TTL 回收 |
| 延迟开销 | 本地环境下隧道转发附加延迟 < 50ms |

## 5. 范围边界（明确不做）

- 不做 UDP / KCP 转发（仅 TCP）
- 不做 TLS 加密隧道（token 明文鉴权即可，留扩展口）
- 不做 Web Dashboard UI（演示链路经隧道访问 demo 服务即满足 localhost 验证）
- 不做多 Client 集群、负载均衡、热更新

## 6. 矛盾与风险记录

- **矛盾检测**：原始 Prompt 无内部冲突。
- **Docker 适配说明**：CLI 工具非天然 Web 服务，按红线 1「适应性」条款采用容器化演示链路策略（见 §3），已在本文档记录，不构成范围漂移。
- **风险**：多路复用若自实现帧协议，需重点测试半包/粘包与流控；建议优先采用成熟库（yamux/smux）以降低风险。
